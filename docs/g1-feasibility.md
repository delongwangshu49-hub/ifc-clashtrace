## Scope

G1 tests one deterministic, programmatically generated IFC4 pipe-wall hard clash. It is a technical spike, not a claim of general clash-detection accuracy and not a product UI.

## Controlled geometry

- Coordinate basis: both files use the same project coordinate system and identity coordination matrix.
- Length unit: metre; IfcOpenShell reports a unit scale of `1.0` to SI for both files.
- Wall: origin `(0, 0, 0)` m; `4.0 × 0.2 × 3.0` m.
- Pipe: axis starts at `(2, -1, 1.5)` m, runs `2.0` m along positive Y, and has radius `0.1` m.
- Reference tolerance: `0.002` m.
- Fixed pipe GUID: `0H4H4H4H514O4H4H4H4H4H`.
- Fixed wall GUID: `0Y8Y8Y8Y928e8Y8Y8Y8Y8Y`.
- Dataset origin: generated by this repository. No public license has been assigned, so redistribution is `false` and the generated IFC files are excluded from the G1 GitHub web checkpoint.

The manifest at `data/generated/g1/manifest.json` records the two IFC SHA-256 values and the expected GUID pair.

## Decision and limitations

- G1 proves both the IfcOpenShell reference route and the browser/Web IFC route are feasible for one known pierce case. The browser route is not frozen or replaced by the Python fallback.
- The browser detector presently proves exact surface intersection for this clearly over-tolerance case. It does not yet implement the complete 2 mm boundary classification, touching exclusion, containment handling, openings, or failure-closed behavior; those remain G2/G3 work.
- The browser route does not claim a reliable penetration distance. Its future Clash Record should keep `penetration_distance_m` as `null` unless G3 establishes a validated calculation.
- IFC element express IDs are model-local and may be equal across the two files; traceability therefore uses model role plus `GlobalId`, not express ID alone.

## Incidents retained as evidence

- The first read-only environment command had an outer-shell quoting error; it made no project change.
- The first Node download attempt was blocked by the sandbox network layer; the approved retry used the same official URLs and passed SHA-256 verification.
- The first npm attempt tried its default user-level cache and was denied; the successful retry used the ignored project-local `tmp/npm-cache`.
- The first reference result reader used attribute syntax for the clash wrapper GUID; the documented `get_argument(0)` access fixed it without changing data or expected results.
- The web-ifc TypeScript declaration exposed `FlatMesh.delete()`, but the runtime callback object did not; removing that invalid cleanup call resolved the mismatch without altering geometry or detection.
- The Chrome connection did not support the requested `networkidle` wait mode; using the supported `load` state produced the same page result and no browser errors.
